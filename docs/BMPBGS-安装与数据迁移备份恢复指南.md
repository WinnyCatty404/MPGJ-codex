# BMPBGS 安装、数据迁移、备份与恢复速查指南

> 版本 v2.0（精简版）｜ 适用产品：BMPBGS 密评协同管理系统（Windows 安装包 / Linux 部署包）｜ 2026-10-17 精简自 v1.0
>
> **修订说明**：① 全文精简，只保留必要内容与步骤；② 修正「恢复」章节——原稿所述"临时数据库切换、失败自动回退、PostgreSQL 自动自愈"与实际脚本行为不符，已按 2026-10-16 事故排查结论改写为真实前置条件与操作步骤。

**核心原则：程序目录与数据目录相互独立。程序可随时替换升级，数据目录一经确定不再变更。** 安装、升级、迁移、备份、恢复五类操作均建立在这条原则之上。

## 一、数据构成

| 目录 | 位置 | 内容 | 升级时 |
|---|---|---|---|
| 程序目录 | 安装时选择，**允许中文**，如 `D:\BMPBGS\App` | 启动器、控制台、私有 Node/PostgreSQL、前后端文件、运维脚本 | 替换 |
| 数据目录 | 安装时指定，**必须纯英文绝对路径**，如 `D:\BMPBGS\Data` | `pgdata`（全部业务数据）、`storage`（项目文件与模板）、`uploads`（上传附件）、`backups`（备份集） | 保持不动 |

备份与恢复同时覆盖 `pgdata` + `storage` + `uploads`，三者必须一致，缺一不可。安装包自带 Node 与 PostgreSQL，目标机只需预装 Microsoft Visual C++ Redistributable（2015–2022，x64）。

## 二、安装

1. 确认 64 位 Windows、磁盘写权限、已装 VC++ Redistributable。
2. 运行安装包：程序目录可含中文；**数据目录必须纯英文绝对路径、本地磁盘、可写，且不得与程序目录相同**。建议同一大文件夹下两个子目录：
   ```
   D:\BMPBGS\
   ├─ App\     ← 程序
   └─ Data\    ← 数据
   ```
3. 安装完成后打开控制台点「启动系统」，首次初始化数据库约 1–2 分钟。
4. 用初始账号 `admin` / `Admin@123` 登录，**立即修改密码**。
5. 批量部署：`BMPBGS-Windows-x64-Setup.exe /VERYSILENT /DATADIR=D:\BMPBGS-Data`。

> 控制台窗口点 `X` 只关窗口、不停服务；「停止系统」才真正结束后台服务。

## 三、升级

1. 控制台点「备份数据」，等待完成。
2. 关闭控制台，确认系统已停止。
3. 运行新安装包：**安装位置与数据存储位置都保持原版本一致**（安装器会自动带出上次数据路径，直接下一步即可）。
4. 启动系统，核对项目列表与报告导出。

升级后：程序文件被覆盖；`pgdata`、`storage\projects`、`uploads` 原地保留；自行修改过的模板默认不被覆盖，随版本更新的记录类模板会被覆盖（按需重新导入）。

**两个高危误操作**：

- **数据目录选成新的空文件夹** → 系统初始化空库，历史项目不可见（旧数据仍在原目录）。处理：重装，数据目录改回原路径。
- **误以为卸载会清数据** → 卸载不删数据目录，「卸载 → 重装 → 选原数据目录」是修复程序损坏的安全路径。

## 四、数据迁移（换机器 / 换目录）

**只用「备份 + 恢复」，不要直接拷贝数据目录。**

1. 源计算机控制台点「备份数据」，记录 `<数据目录>\backups\<时间戳>`。
2. 将整个备份集文件夹复制到目标计算机（自包含：dump + storage + uploads）。
3. 目标机安装 BMPBGS，数据目录选**新的空英文目录**。
4. 按第六节恢复该备份集。
5. 恢复后启动系统，核对：项目数量一致；随机开两个项目，记录与证据图片正常；导出一次 Word 报告；在目标机再备份一次。

仅当两端数据库主版本一致、且源系统已完全停止时，才可直拷数据目录；任一不满足都不要用。

## 五、备份

- **输出**：`<数据目录>\backups\<yyyyMMdd-HHmmss>\`，含 `bb_miping-<时间戳>.dump`（PostgreSQL 自定义格式全量转储）+ `storage\` + `uploads\`。
- **操作**：控制台「备份数据」（推荐）/ 开始菜单快捷方式 / 程序目录执行 `bb-backup.ps1`。
- **前提**：PostgreSQL 必须在运行（系统已启动）。
- **策略**：升级、迁移、恢复、批量调整前先备份；每工作日结束前备一次、保留两周；最新备份集异地保存；每季度用最近备份集完整演练一次恢复。

## 六、恢复

**恢复会用选定备份覆盖当前数据库与文件，执行前确认现有数据可弃或已备份。**

**前置条件（关键）**：恢复脚本必须连上本机 PostgreSQL 才能重建数据库——**PostgreSQL 未运行时恢复会直接失败**（控制台「停止系统」会连同 PostgreSQL 一起停止，踩过这个坑）。

操作步骤：

1. **确保 PostgreSQL 在运行**：系统正在运行即可；若已停止，先点「启动系统」（pgdata 丢失时会自动重建空库，不影响恢复），或执行：
   ```powershell
   & "D:\BMPBGS\pgsql\bin\pg_ctl.exe" -D "D:\BMPBGS-Data\pgdata" -l "D:\BMPBGS-Data\pgdata\postgresql.log" start
   ```
2. **执行恢复**（二选一）：
   - 系统开着，PowerShell 直接执行（脚本会先踢掉后端连接，恢复后连接池自动重连）：
     ```powershell
     powershell -ExecutionPolicy Bypass -File "D:\BMPBGS\bb-restore.ps1" -BackupSet "<备份集完整路径>" -Silent
     ```
   - 或控制台点「恢复数据」选备份集（需先停止前后端但保留 PostgreSQL 运行）。
3. **重启验证**：恢复完成后点「启动系统」，浏览器 Ctrl+F5，按第四节核对清单检查。

**注意**：恢复期间不要断电；失败时先看日志、不要反复重试；恢复后不重启系统看不到数据。

> 已知问题（2026-10-16）：控制台「停止系统 → 恢复数据」路径目前必然失败（停止即停 PostgreSQL，恢复又要求其在运行），修复方案见 `docs/恢复数据按钮失效-问题分析与修复方案-v1.0.md`。按本节前置条件操作可正常恢复。

## 七、Linux 部署包

`/opt/BMPBGS`，systemd 运行；对应脚本 `bb-start.sh` / `bb-stop.sh` / `bb-backup.sh` / `bb-restore.sh`；目录结构与备份、恢复语义同 Windows，本文原则同样适用。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 数据目录被拒绝 | 含中文 / 非绝对路径 / 不可写，改纯英文绝对路径 |
| 打开系统项目列表为空 | 数据目录指向了空目录，重装改回原路径 |
| 首次启动慢 | 初始化数据库，1–2 分钟正常 |
| 备份失败 | 系统未启动或数据库被停，先启动再备 |
| 恢复报"无法校验 PostgreSQL 实例身份" | PostgreSQL 没在运行，按第六节先拉起 PG 再恢复 |
| 恢复后看不到数据 | 恢复后未重启系统，点「启动系统」并刷新浏览器 |
| 卸载后数据还在吗 | 在，设计行为；清理需手工删数据目录 |
| 忘记 admin 密码 | 维护人员直接重置数据库，重置前先备份 |
