# BMPBGS 安装、数据迁移、备份与恢复速查指南

> 版本 v2.1｜ 适用产品：BMPBGS 密评协同管理系统（Windows 安装包 / Linux 部署包）｜ 2026-10-17 更新
>
> **修订说明**：① v2.0 全文精简，只保留必要内容与步骤；② v2.1 按升级后的脚本重写「备份」「恢复」两章——备份新增本地 + NAS 双通道，恢复新增"先下载校验、后临时库切换、失败自动回退、PostgreSQL 自动初始化"，v2.0 中"PostgreSQL 必须在运行"等前置警示已过时。

**核心原则：程序目录与数据目录相互独立。程序可随时替换升级，数据目录一经确定不再变更。** 安装、升级、迁移、备份、恢复五类操作均建立在这条原则之上。

## 一、数据构成

| 目录 | 位置 | 内容 | 升级时 |
|---|---|---|---|
| 程序目录 | 安装时选择，**允许中文**，如 `D:\BMPBGS\App` | 启动器、控制台、私有 Node/PostgreSQL、前后端文件、运维脚本 | 替换 |
| 数据目录 | 安装时指定，**必须纯英文绝对路径**，如 `D:\BMPBGS\Data` | `pgdata`（全部业务数据）、`storage`（项目文件与模板）、`uploads`（上传附件）、`backups`（备份集） | 保持不动 |

备份与恢复同时覆盖 `pgdata` + `storage` + `uploads`，三者必须一致，缺一不可。安装包自带 Node 与 PostgreSQL，目标机只需预装 Microsoft Visual C++ Redistributable（2015–2022，x64）。

## 二、安装

1. 确认 64 位 Windows、磁盘写权限、已装 VC++ Redistributable。
2. 运行安装包：程序目录可含中文；**数据目录必须纯英文绝对路径、本地磁盘、可写，且不得与程序目录相同**。建议同一大文件夹下两个子目录：
   ```
   D:\BMPBGS\
   ├─ App\     ← 程序
   └─ Data\    ← 数据
   ```
3. 安装完成后打开控制台点「启动系统」，首次初始化数据库约 1–2 分钟。
4. 用初始账号 `admin` / `Admin@123` 登录，**立即修改密码**。
5. 批量部署：`BMPBGS-Windows-x64-Setup.exe /VERYSILENT /DATADIR=D:\BMPBGS-Data`。

> 控制台窗口点 `X` 只关窗口、不停服务；「停止系统」才真正结束后台服务。

## 三、升级

1. 控制台点「备份数据」，等待完成。
2. 关闭控制台，确认系统已停止。
3. 运行新安装包：**安装位置与数据存储位置都保持原版本一致**（安装器会自动带出上次数据路径，直接下一步即可）。
4. 启动系统，核对项目列表与报告导出。

升级后：程序文件被覆盖；`pgdata`、`storage\projects`、`uploads` 原地保留；自行修改过的模板默认不被覆盖，随版本更新的记录类模板会被覆盖（按需重新导入）。

**两个高危误操作**：

- **数据目录选成新的空文件夹** → 系统初始化空库，历史项目不可见（旧数据仍在原目录）。处理：重装，数据目录改回原路径。
- **误以为卸载会清数据** → 卸载不删数据目录，「卸载 → 重装 → 选原数据目录」是修复程序损坏的安全路径。

## 四、数据迁移（换机器 / 换目录）

**只用「备份 + 恢复」，不要直接拷贝数据目录。**

1. 源计算机控制台点「备份数据」，记录 `<数据目录>\backups\<时间戳>`。
2. 将整个备份集文件夹复制到目标计算机（自包含：dump + storage + uploads）；已配置 NAS 备份时可跳过拷贝，直接在目标机从 NAS 备份集恢复（见第六节）。
3. 目标机安装 BMPBGS，数据目录选**新的空英文目录**。
4. 按第六节恢复该备份集。
5. 恢复后启动系统，核对：项目数量一致；随机开两个项目，记录与证据图片正常；导出一次 Word 报告；在目标机再备份一次。

仅当两端数据库主版本一致、且源系统已完全停止时，才可直拷数据目录；任一不满足都不要用。

## 五、备份（本地 + NAS）

- **本地备份**：输出 `<数据目录>\backups\<yyyyMMdd-HHmmss>\`，含 `bb_miping-<时间戳>.dump`（PostgreSQL 自定义格式全量转储）+ `storage\` + `uploads\` + `backup-manifest.json`（文件大小与 SHA256 校验清单）。写入采用"先临时目录、后定名"的原子切换，不会留下写了一半的备份集。
- **NAS 备份（可选，推荐）**：控制台「⚙ 设置」中启用远程备份、填写 NAS 的 UNC 路径（如 `\\NAS\BMPBGS-Backup`），点「检测连接」通过即配置完成。BMPBGS 不保存 NAS 密码，直接使用 Windows 已记住的网络凭据。本地备份成功后，自动把同一份备份集上传到 NAS。
- **操作**：控制台「备份数据」（推荐，可在备份集选择器中查看本地 / NAS 两侧的备份集与状态）/ 开始菜单快捷方式 / 程序目录执行 `bb-backup.ps1`。控制台会显示任务退出码：`0` 成功（含 NAS 上传）；`2` 本地成功但 NAS 上传失败（本地集已保留，控制台弹窗可一键重试上传）；其他代码为失败。
- **前提**：PostgreSQL 必须在运行（系统已启动）。
- **NAS 上传报错误 1219**：Windows 对同一台服务器只保留一套网络凭据。在「⚙ 设置」点「打开 NAS 并登录」，用资源管理器重新登录一次 NAS，再重试备份。
- **策略**：升级、迁移、恢复、批量调整前先备份；每工作日结束前备一次，本地保留两周、NAS 长期保留；每季度用最近备份集完整演练一次恢复。

## 六、恢复

**恢复会用选定备份覆盖当前数据库与文件，执行前确认现有数据可弃或已备份。**

**流程（新版脚本，2026-10-17 起）**：全程"先校验、后破坏"，任一步失败自动回退，现有数据保持原样——

1. **NAS 源先下载校验**：选择 NAS 备份集时，先把备份集完整下载到本地并逐项校验（清单、文件大小、SHA256、dump 可读性），**此阶段不停止任何服务**；下载或校验失败直接退出（exit 1），现有数据零改动。
2. **只停 Web/API**：脚本只停止前后台服务，PostgreSQL 未运行会被自动拉起；pgdata 若被删除，会初始化一个最小集群来接管数据——不再需要人工先启动 PG。
3. **临时库切换**：先恢复到临时数据库 `bb_restore_<标签>` 并校验核心表齐全，通过后把原库改名 `bb_before_<标签>` 留存、临时库顶名上线；`storage` / `uploads` 同样先暂存再切换。
4. **失败全量回退**：任一步失败即还原数据库名、还原文件、清理暂存目录，回到执行前状态。

操作步骤：

1. 控制台点「恢复数据」，在备份集选择器中选**本地**或 **NAS**来源，再选中目标备份集（状态列显示"完整备份 / 旧版备份；恢复前将预检 / 不可用：原因"）。
2. 确认后自动执行：NAS 源先下载校验（不停服务）→ 停 Web/API → 恢复与切换 → 完成后提示"Web/API 当前保持停止，请在控制台点击'启动系统'"。
3. **重启验证**：点「启动系统」，浏览器 Ctrl+F5，按第四节核对清单检查。

> 命令行方式（批量 / 无人值守）：`powershell -ExecutionPolicy Bypass -File "<程序目录>\bb-restore.ps1" -BackupSet "<备份集路径或 NAS UNC 路径>" -Silent`；退出码 `0` 成功、`1` 失败（失败时现有数据未修改）。

**注意**：恢复期间不要断电；失败时先看控制台日志、不要反复重试；恢复后不点「启动系统」看不到数据。原库会以 `bb_before_<标签>` 保留在 PostgreSQL 中，确认新数据无误后可手工清理。

## 七、Linux 部署包

`/opt/BMPBGS`，systemd 运行；对应脚本 `bb-start.sh` / `bb-stop.sh` / `bb-backup.sh` / `bb-restore.sh`；目录结构与备份、恢复语义同 Windows，本文原则同样适用。

## 八、常见问题

| 现象 | 处理 |
|---|---|
| 数据目录被拒绝 | 含中文 / 非绝对路径 / 不可写，改纯英文绝对路径 |
| 打开系统项目列表为空 | 数据目录指向了空目录，重装改回原路径 |
| 首次启动慢 | 初始化数据库，1–2 分钟正常 |
| 备份失败 | 系统未启动或数据库被停，先启动再备 |
| 本地备份成功但 NAS 没有 | 退出码 2：NAS 未连通；控制台弹窗可重试上传，或进「⚙ 设置」重新登录 NAS（1219 错误用「打开 NAS 并登录」） |
| 恢复报"无法校验 PostgreSQL 实例身份" | 新版脚本会自动拉起 / 初始化 PostgreSQL；若仍报错，检查程序目录 pgsql 是否完整 |
| 恢复后看不到数据 | 恢复后未点「启动系统」，启动系统并刷新浏览器 |
| 卸载后数据还在吗 | 在，设计行为；清理需手工删数据目录 |
| 忘记 admin 密码 | 维护人员直接重置数据库，重置前先备份 |
