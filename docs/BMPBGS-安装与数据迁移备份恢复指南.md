# BMPBGS 安装、升级、数据迁移、备份与恢复操作指南

> 文档版本：v1.0 ｜ 适用产品：BMPBGS 密评协同管理系统（Windows 安装包 / Linux 部署包） ｜ 发布日期：2026 年 10 月

本指南用于指导 BMPBGS 密评协同管理系统的部署、升级、数据迁移与数据保护操作。文档面向负责安装与维护系统的技术人员，覆盖 Windows 安装包（主推）与 Linux 部署包两种形态，重点说明**数据存储位置的规划原则**以及**备份与恢复的标准流程**。

阅读本指南前，请先明确一条核心原则：**程序目录与数据目录相互独立，程序可以随时替换升级，数据目录一经确定就不要再变更。** 后文的升级、迁移、备份、恢复四类操作，均建立在这一原则之上。

## 执行摘要

本指南面向 BMPBGS 密评协同管理系统的部署与运维人员，说明安装、升级、数据迁移、备份与恢复五类操作的标准流程与风险控制要求。全文围绕一条核心原则展开：**程序目录与数据目录相互独立，程序可以随时替换升级，数据目录一经确定不再变更。**

- 安装阶段的关键约束是数据目录：必须为本地磁盘的纯英文绝对路径，且不得与程序目录混用。
- 升级阶段的正确做法是保持原数据目录不变，安装程序会自动读取上次记录的路径并填入。
- 数据迁移优先采用「备份 + 恢复」，仅在同数据库主版本且源系统完全停止时可直拷贝目录。
- 备份同时覆盖数据库、`storage` 与 `uploads`；恢复为破坏性操作，执行后必须重启系统。

## 一、系统运行形态与数据构成

### 1.1 程序与数据分离的部署结构

BMPBGS 安装后由两部分组成，二者物理分离，职责清晰：

| 部分 | 默认位置 | 内含 | 升级时是否替换 |
| --- | --- | --- | --- |
| 程序目录 | `%LOCALAPPDATA%\BMPBGS` | 启动器 `BMPBGS.exe`、控制台、私有 Node 运行时、私有 PostgreSQL 二进制、后端与前端静态文件、运维脚本 | 替换 |
| 数据目录 | 安装时自行指定，默认 `<安装盘>\BMPBGS-Data` | `pgdata`（数据库）、`storage`（项目文件与模板）、`uploads`（上传附件）、`backups`（备份输出） | 保持不动 |

安装包自带 Node.js 与 PostgreSQL，目标计算机**不需要预装任何运行时**。唯一的前置组件是 Microsoft Visual C++ Redistributable（2015–2022，x64），PostgreSQL 的 Windows 版本依赖它，绝大多数计算机已自带。

### 1.2 数据目录是整个系统的资产所在

数据目录内的四个子目录分别承担不同职责，理解它们有助于判断备份与恢复的覆盖面：

- `pgdata`：PostgreSQL 数据目录，存放用户、项目、资产、测评记录、风险、审核结论等全部结构化数据。
- `storage`：项目文件与报告模板，包含每个项目的证据图片、生成文档与模板资源。
- `uploads`：通过界面上传的附件。
- `backups`：备份输出目录，每次备份生成一个以时间戳命名的新备份集。

> **要点**：备份与恢复同时覆盖数据库与 `storage`、`uploads` 两个文件目录，三者必须保持一致，缺一不可。

## 二、安装

### 2.1 安装前准备

1. 确认操作系统为 64 位 Windows，当前登录账户对计划使用的磁盘具有写权限。
2. 确认已安装 Microsoft Visual C++ Redistributable（2015–2022，x64）。若缺失，先安装后继续。
3. 规划两个路径。建议采用「同一个大文件夹、两个子目录」的形态，便于整体搬迁与备份：

```
D:\BMPBGS\
├─ App\     ← 程序安装位置
└─ Data\    ← 数据存储位置
```

4. 若该计算机上已有旧版本，先阅读第三章「升级安装」，不要在未确认数据目录的情况下直接安装。

### 2.2 安装步骤

1. 运行安装包 `BMPBGS-Windows-x64-Setup.exe`。
2. 在**安装位置**页选择程序目录，例如 `D:\BMPBGS\App`。该路径**允许包含中文**。
3. 在**数据存储位置**页填写数据目录，例如 `D:\BMPBGS\Data`。该路径有硬性要求，见 2.3。
4. 按向导完成安装。安装程序会创建开始菜单与桌面快捷方式「BMPBGS」。
5. 双击快捷方式打开控制台，点击「启动系统」。首次启动需要初始化数据库，约需 1–2 分钟，完成后浏览器会自动打开系统页面。
6. 使用初始账号 `admin` 登录，初始密码见 2.5，登录后立即修改。

### 2.3 数据存储位置的硬性要求

数据目录是本指南中约束最严格的一项，安装程序会在向导中实时校验：

- 必须是**本地磁盘的英文绝对路径**，形如 `D:\BMPBGS\Data`。禁止使用中文路径，否则 PostgreSQL 初始化会因编码问题直接失败。
- 必须是绝对路径且以盘符开头，长度不少于 4 个字符。
- 目录必须可创建、可写入。校验失败时向导会弹出提示并阻止继续。
- 不建议选择网络盘、映射盘或同步盘（如网盘同步目录），数据库文件在同步过程中可能损坏。

> **易错点**：把数据目录设为**程序目录本身**（例如两者都填 `D:\BMPBGS`）。这样运行期的 `storage\projects` 会与程序自带的 `storage\templates` 混在同一层，日后手工清理程序目录时极易连带删除项目数据。请始终分成两个子目录。

### 2.4 静默安装

批量部署时可以使用命令行参数指定数据目录，跳过交互：

```
BMPBGS-Windows-x64-Setup.exe /VERYSILENT /DATADIR=D:\BMPBGS-Data
```

### 2.5 初始账号与首次配置

- 初始管理员账号：`admin`，初始密码：`Admin@123`。
- **首次部署后必须立即修改**默认管理员密码。
- 系统首次启动时会探测空闲端口并固定下来，写入程序目录下的配置文件持久化保存，后续重启沿用同一套端口，不会因端口漂移导致访问地址变化。

### 2.6 控制台窗口与后台服务

- 系统成功启动后，「启动系统」按钮会变为禁用状态；停止完成或启动失败后才重新可用。
- 点击右上角 `X` 只关闭控制台窗口，不会停止 PostgreSQL、API 或 Web，已打开的系统仍可继续使用。
- 真正结束后台服务必须点击「停止系统」。日常下班无需停止；关机、重启、迁移或维护前建议先停止。
- 控制台可调整大小和最大化，不再始终置顶；日志可手工上翻，也可点击「滚动到底部」或「打开日志」。

## 三、升级安装

### 3.1 标准流程

1. 打开控制台，点击「备份数据」，等待提示备份完成。
2. 关闭控制台窗口，确保系统已停止运行。
3. 运行新版本安装包。
4. **安装位置页保持与原版本一致**；**数据存储位置页保持与原数据目录一致**。安装会读取程序目录中记录的路径并自动填入，通常直接点击下一步即可。
5. 安装完成后打开控制台，点击「启动系统」。

### 3.2 升级时各类资源的变化

| 资源 | 升级后的状态 |
| --- | --- |
| 程序文件 | 被新版本覆盖 |
| 数据库 `pgdata` | 原地保留，历史项目与账号不受影响 |
| `storage\projects`、`uploads` | 原地保留 |
| 自行修改过的模板 | 默认不被覆盖 |
| 随版本更新的记录类模板 | 被覆盖，安装完成页会提示「模板已更新，如您此前自行修改过模板，请按需重新导入或替换」 |
| 备份目录 | 继续使用原数据目录下的 `backups` |

### 3.3 升级中的两个高危误操作

**误操作一：数据目录选成了新的空文件夹。** 系统会初始化一套全新的空数据库，历史项目在新环境中不可见。旧数据不会丢失，仍保留在原数据目录中，但程序不再指向它。处理方法：重新运行安装包，把数据目录改回原路径。

**误操作二：误以为卸载会清除数据。** 安装程序有意不配置卸载清理逻辑，卸载后数据目录完整保留。因此「卸载 → 重新安装 → 选择原数据目录」这一路径是安全的，可用于修复程序文件损坏等问题。需要彻底清理时，请手工删除数据目录，且删除前务必确认不再需要其中的项目数据。

## 四、数据迁移

数据迁移指更换计算机或更换数据目录位置。**推荐始终使用「备份 + 恢复」方式**，不建议直接拷贝数据目录。

### 4.1 推荐方式：备份与恢复（跨机器、跨版本均适用）

1. 在源计算机打开控制台，点击「备份数据」，记录备份集路径，通常为 `<原数据目录>\backups\<时间戳>`。
2. 将整个备份集文件夹复制到目标计算机，或复制到移动存储介质中转。备份集自包含：数据库转储文件 + `storage` + `uploads`。
3. 在目标计算机安装 BMPBGS，数据目录选择一个**新的、空的英文目录**。
4. 打开控制台，点击「恢复数据」，按提示选择复制过来的备份集。
5. 恢复完成后点击「启动系统」，再登录核对项目与证据图片。

### 4.2 直接拷贝数据目录的适用条件

只有当源与目标计算机的**数据库主版本完全一致**、且源系统**已完全停止运行**（控制台点击「停止系统」，进程已退出）时，才可以直接复制整个数据目录到新位置，并在安装时把数据目录指向该位置。任何一条不满足都不要使用此方式，否则可能出现数据库无法启动或数据不一致。

### 4.3 迁移后的核对清单

1. 项目列表数量与迁移前一致。
2. 随机打开两个项目，确认现场测评记录、证据图片可正常显示。
3. 导出一次 Word 报告，确认模板与数据绑定正常。
4. 在目标计算机上重新执行一次备份，确认备份链路可用。

## 五、备份

### 5.1 备份内容与输出位置

每次备份生成一个独立备份集，输出到数据目录下的 `backups\<yyyyMMdd-HHmmss>`，内含：

- `bb_miping-<时间戳>.dump`：数据库转储文件，采用 PostgreSQL 自定义格式，包含全部结构化数据。
- `storage\`：项目文件与模板副本。
- `uploads\`：上传附件副本。

### 5.2 操作方式

| 方式 | 操作 |
| --- | --- |
| 控制台（推荐） | 打开「BMPBGS」控制台，点击「备份数据」 |
| 快捷方式 | 开始菜单中的「备份BMPBGS数据」 |
| 命令行 | 在程序目录执行 `bb-backup.ps1` |

备份期间 PostgreSQL 必须处于运行状态。若提示备份失败，首先确认系统已启动（控制台状态显示为运行中），其次确认数据库服务未被人为停止。

### 5.3 备份策略建议

- **操作前先备份**：升级、迁移、恢复、批量数据调整之前，一律先执行一次备份。
- **日常频率**：建议每个工作日结束前备份一次，保留最近两周的备份集。
- **异地保存**：定期把最新备份集复制到另一台计算机或存储介质。备份集在同一块磁盘上无法抵御磁盘故障。
- **定期演练**：每季度在测试环境用最近一次的备份集完整走一遍恢复流程，确认备份可用。未经恢复验证的备份不能算作有效备份。

## 六、恢复

### 6.1 恢复会覆盖现有数据

恢复操作会用选定备份覆盖当前数据。系统会先恢复到临时数据库和临时文件目录，通过校验后才切换；失败时尝试回退原数据。开始前仍需确认：

1. 目标数据目录中的现有数据确实不需要保留，或已完成备份。
2. 待恢复的备份集来自可信来源，且时间点符合预期。

### 6.2 操作步骤

1. 打开控制台。系统当前运行或已经停止都可以执行恢复。
2. 点击「恢复数据」；控制台会自动停止 Web/API，并根据需要启动或初始化 PostgreSQL。
3. 在可用备份集列表中，按时间戳选择要恢复的那一个。列表按时间倒序排列，最新备份排在最前。
4. 等待执行完成。恢复过程先验证备份，再恢复到临时数据库和临时文件目录；全部成功后才切换，失败时自动回退现有数据。
5. 恢复完成后点击「启动系统」，使应用加载恢复后的数据。
6. 登录系统，按 4.3 的核对清单检查数据完整性。

### 6.3 恢复过程中的注意事项

- 恢复期间不要关闭计算机或中断电源；维护任务完成前控制台会阻止关闭，以免用户失去进度和失败提示。
- PostgreSQL 已停止或 `pgdata` 已被删除时，恢复脚本会安全自愈；目录非空但缺少 `PG_VERSION` 时会拒绝覆盖并提示人工检查。
- 若恢复失败，请根据控制台提示打开日志；脚本会尽可能回退原数据库和文件目录，不要在未核实状态前反复操作。
- 恢复完成后 Web/API 保持停止，必须点击「启动系统」。

## 七、Linux 部署包的对应关系

除 Windows 安装包外，项目还提供 Linux 部署包，功能一致，用于 openEuler、统信 UOS 服务器版、麒麟、CentOS/RHEL 8 等 glibc 2.28 及以上版本的 x86_64 发行版。

- 安装后目录为 `/opt/BMPBGS`，以 systemd 服务方式运行。
- 对应脚本：`bb-start.sh`（启动）、`bb-stop.sh`（停止）、`bb-backup.sh`（备份）、`bb-restore.sh`（恢复）。
- 数据目录与备份集的内部结构、备份与恢复的语义与 Windows 版本一致，第二章至第六章所述原则同样适用。

## 八、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 安装时数据目录被拒绝 | 路径含中文、非绝对路径或不可写。改用纯英文绝对路径，例如 `D:\BMPBGS\Data` |
| 安装后打开系统看到空项目列表 | 数据目录很可能指向了新的空目录。重新安装并将数据目录改回原路径 |
| 首次启动等待时间较长 | 首次启动需初始化数据库，约 1–2 分钟属正常现象 |
| 升级后部分模板内容与原来不同 | 随版本更新的记录类模板会被覆盖，安装完成页有提示。重新导入自行修改过的模板即可 |
| 备份失败 | 常见原因是系统未启动或数据库服务被停止。先确认控制台状态为运行中，再重试 |
| 恢复后看不到新数据 | 恢复完成后未重新启动系统。点击「启动系统」并刷新浏览器 |
| 卸载后数据是否还在 | 数据目录完整保留，这是设计行为。需要清理时手工删除数据目录 |
| 忘记管理员密码 | 需要由维护人员通过数据库直接重置，请在重置前先完成一次备份 |

## 九、注意事项速查

**安装阶段**

1. 程序目录与数据目录分开放，建议同一大文件夹下的两个子目录。
2. 数据目录必须纯英文、绝对路径、本地磁盘、可写。
3. 不要把数据目录设为程序目录本身。
4. 安装完成后立即修改默认管理员密码。

**升级阶段**

5. 升级前先备份。
6. 安装位置与数据目录都与原版本保持一致。
7. 升级后核对项目列表与报告导出是否正常。

**迁移阶段**

8. 优先使用「备份 + 恢复」，不要直接拷贝数据目录。
9. 迁移后在目标机器上重新执行一次备份，确认链路可用。

**备份与恢复**

10. 备份同时覆盖数据库、`storage` 与 `uploads`，恢复时三者一起还原。
11. 恢复是破坏性操作，执行前确认现有数据可被覆盖。
12. 恢复完成后必须重启系统。
13. 备份集定期异地保存，并每季度演练一次恢复。
