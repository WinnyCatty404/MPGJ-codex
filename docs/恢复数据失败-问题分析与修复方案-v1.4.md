# 恢复、备份与控制台稳定性复核（v1.4）

## 1. 本版范围

本版在 v1.3 的基础上补齐 2026-10-17 后续提交的复核结果，并处理仍可复现的“控制台日志最后一行显示不完整”。本次只修改源码、测试和说明文档，没有执行真实备份、恢复、服务启停，也没有改动数据库、附件目录、NAS 或安装版运行目录。

## 2. 提交复核结论

从提交 `38b99e2e1b0a0ba8ca7cbcb45fee47bb4bc657e7` 之后的恢复与控制台改动总体方向正确：恢复前预检、临时库恢复、附件临时目录、失败回退、实例身份校验和端口真实可绑定检查均能降低误恢复与半恢复风险。昨天界面显示“恢复成功”说明任务脚本给出了成功结果，但是否恢复到预期时间点仍应由用户核对项目数量、关键项目内容和附件。

复核中发现并补齐以下边界：

1. NAS 单独重试原来仍输出 `BB_TASK_OK=backingup`，控制台等待的是 `remoteupload`，可能把成功上传显示为结果不明。
2. NAS 上传失败与 Web/API 自动重启失败同时发生时，退出码可能不可读，原逻辑可能无法稳定表达“本地成功、远程失败、服务未恢复”。
3. 备份前是否存在 Web/API 仍使用连接表判断，可能受到 PID 0 过期监听项影响。
4. NAS 同名备份原来主要比较 dump；数据库相同但附件不同仍可能被当作同一备份。
5. Windows PowerShell 5.1 遇到 `HTTPS_PROXY` / `https_proxy` 等重复键时，`Start-Process` 可能失败。
6. RichTextBox 即使多次滚动到底部，在自动换行、DPI 缩放和控件重排后仍可能裁掉末行；继续叠加滚动消息不能从结构上解决。

## 3. 本版实现

### 3.1 任务结果协议

- 公共函数统一解析 `BB_TASK_OK`、`BB_REMOTE_BACKUP_FAILED`、`BB_BACKUP_RESTART_FAILED` 与退出码。
- 成功标记必须和当前任务种类完全一致，嵌套停止脚本不能冒充恢复成功。
- 远程上传重试成功时输出 `BB_TASK_OK=remoteupload`。
- NAS 失败优先于服务重启失败显示；即使退出码不可读，也能保留本地备份成功、远程失败的准确语义。
- 若 NAS 与服务重启同时失败，控制台提示两件事，并将系统状态设为停止，避免误显示为运行中。

### 3.2 备份完整性

- 备份前端口状态改用独占绑定探测，避开连接表的过期 PID 0 项。
- 第 2 版清单强制要求 dump、storage、uploads 三类 SHA256 信息；缺失即判无效。
- NAS 已存在同名备份时，同时比较数据库、storage 与 uploads 的文件数、字节数和目录指纹。
- NAS 临时副本完成后同样进行三部分对比，任一不一致都不会改名为正式备份集。
- v1 与无清单历史备份继续兼容，通过深度读取时现算目录指纹。

### 3.3 启动兼容性

- 启动前仅在当前进程范围内规范化大小写重复的代理环境变量。
- 不记录代理值，不修改用户级或系统级环境变量。

### 3.4 日志显示

- 日志控件由 RichTextBox 改为只读 DataGridView，每条日志独立成行并自动计算行高。
- 顶部、状态、日志、底部按钮统一放入四行 TableLayoutPanel，底部按钮不会覆盖日志视口。
- 用户向上滚动时自动暂停跟随；重新滚到底部或点击“滚动到底部”后恢复跟随。
- 内存中保留最近 2000 行，超过后分批移除旧行；完整历史仍写入本地日志文件。
- 调整窗口大小或最大化后，开启跟随时重新定位末行。

## 4. 安全边界

- 恢复的数据库切换和附件替换发生在预检之后，失败时按既有流程回退。
- “控制台显示成功”不能代替业务数据核验；建议抽查一个近期项目、一个历史项目及各自附件。
- 源码静态/临时目录测试不触碰真实数据。安装版同步与真实端到端演练应在用户明确安排维护窗口后单独进行。
- 不应为了验证再次手动删除真实数据库或附件。若需演练，应使用独立临时数据目录和测试实例。

## 5. 验证项目

本版测试应覆盖：

- PowerShell 语法与 UTF-8 BOM。
- 退出码不可读但有正确任务标记时成功。
- 嵌套 `stopping` 标记不能让 `restoring` 成功。
- NAS 失败与服务重启失败同时出现时，NAS 部分成功语义优先且保留重启失败标记。
- 同名 NAS 备份附件被修改时拒绝复用。
- 第 2 版清单缺少任一校验值时拒绝使用。
- 日志界面不再创建 RichTextBox，并使用独立行布局和根表格布局。

## 6. 尚未宣称完成的验证

本次没有对真实安装版进行“备份 → 修改测试数据 → 恢复 → 业务与附件核对”的端到端演练，也没有在 100%、125%、150% 缩放下人工观察窗口。因此，源码修复和自动检查通过后，仍建议用户在安装版中手动确认：末行完整显示、向上滚动暂停跟随、点击按钮恢复跟随，以及备份/恢复提示与实际状态一致。
