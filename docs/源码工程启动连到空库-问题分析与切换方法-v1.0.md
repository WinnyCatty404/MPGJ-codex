# 源码工程启动连到安装版空库——问题分析与切换方法

> 版本 v1.0 · 2026-10-17
>
> **结论先行**：这是两套实例共用 54328 端口导致的“串台”——安装版那套进程（含昨天自动新建的空库）一直没停、占着 54328；从源码工程手动启动后端没有端口避让逻辑，默认就连 54328，于是连上了空库。切换方法：停掉安装版 → 用 `bb-start.ps1` 从源码工程根启动，它会自动落到源码工程自己的库 `D:\BBMipingDB\data`。

---

## 1. 背景

机器上存在**两套 BMPBGS 实例**，端口配置相同（PostgreSQL 54328 / 后端 3100 / 前端 5173），互相排斥：

| | 安装版 | 源码工程版 |
|---|---|---|
| 程序目录 | `D:\BMPBGS` | `E:\02密评\BBMPGJ\MPJG-CODEX-MASTER` |
| 数据目录 | `D:\BMPBGS-Data`（pgdata / storage / uploads / backups，由 `bb-data-path.txt` 记录） | `D:\BBMipingDB\data`（库）+ 工程内 `storage\projects`（附件） |
| 数据状态 | 昨天 22:59 被自动 initdb 的**空库**（projects=0，仅种子账号） | 昨天 18:20 的真实数据 |
| 路径解析依据 | 存在 `bb-data-path.txt` → 强制用 `D:\BMPBGS-Data\pgdata` | 无 `bb-data-path.txt`/`bb-config.json` + 含 `.git` + `D:\BBMipingDB\data\PG_VERSION` 存在 → 落到 `D:\BBMipingDB\data` |

> 安装版空库的来历：昨天用户手删 pgdata/storage 后「恢复数据」静默失败，重启时 bb-start 自动 initdb 了新库——详见 `docs/恢复数据按钮失效-问题分析与修复方案-v1.0.md`。

**事发**：安装版三件套从昨天 23:00 启动后一直未停止（PG 占 54328、后端占 3100、前端占 5173）；用户今天从源码工程启动进程，界面连到了昨天那个空库。

## 2. 原因

1. **直接原因：源码后端是手动启动的**（`npm run dev` → `node --watch dist/server.js`），没有走 `bb-start.ps1`。
   - 手动启动不具备端口避让和数据目录解析能力；
   - `backend/src/server.ts` 第 47-48 行：未设置 `DATABASE_URL` 环境变量时，连接串默认写死为 `postgresql://bb_miping_app:...@127.0.0.1:54328/bb_miping`；
   - 此时 54328 上监听的正是安装版的空库 → 源码后端连上空库；
   - 同时 3100 被安装版后端占用，源码后端实际无法完成监听（进程随后退出）。
2. **根因：两套实例共用 54328 端口**，且安装版那套整天未停，端口与空库一直被其占据。

## 3. 解决方案（切换到源码工程自己的库）

**第 1 步：停掉安装版**，释放 54328 / 3100 / 5173：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\BMPBGS\bb-stop.ps1" -Silent
```

（或打开 BMPBGS 控制台点「停止系统」。安装版当前是空库，停止无数据损失。）

**第 2 步：从源码工程根目录用脚本启动**（关键：此后不要手动 `node` / `npm run dev` 起后端）：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\02密评\BBMPGJ\MPJG-CODEX-MASTER\bb-start.ps1"
```

启动脚本会自动完成路径解析：源码根无 `bb-data-path.txt`、无 `bb-config.json`、含 `.git` 且 `D:\BBMipingDB\data\PG_VERSION` 存在 → **使用 `D:\BBMipingDB\data`**；54328 已释放则直接使用，未释放会自动避让到下一个空闲端口。启动日志中打印 **“数据库目录：D:\BBMipingDB\data”** 即为正确。

**第 3 步：验证**：浏览器打开启动日志给出的地址（默认 http://localhost:5173 ），登录后查看项目列表是否有数据。

启动完成后，源码工程根会生成 `bb-config.json`（固化 pgPort 与 pgData 映射），之后从源码启动都固定使用这份库。

## 4. 注意事项

1. **两套实例永远不要同时启动**。安装版启动时若检测到 54328 被其他实例占用，会报错拒绝启动（身份校验保护，提交 d2bb6f4）——看到报错不要绕过，先停掉另一套。
2. **源码库数据截至昨天 18:20**；安装版那份 16:13 的备份集（`D:\BMPBGS-Data\backups\20261016-161317`）尚未恢复，属于另一条线，与本次切换互不影响。
3. **附件 storage 不互通**：源码工程的附件在工程内 `storage\projects`，安装版在 `D:\BMPBGS-Data\storage`，切换实例后早期项目的附件目录可能对不上。
4. **源码工程启后端必须走 `bb-start.ps1`**：手动 `node`/`npm run dev` 没有端口避让，必然再次串台。
