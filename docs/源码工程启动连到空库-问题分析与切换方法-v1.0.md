# 源码工程启动连到安装版空库——问题分析与切换方法

> 版本 v1.0 · 2026-10-17
>
> **结论先行**：这是两套实例共用 54328 端口、且源码后端曾在缺少明确配置时默认连接 54328 导致的“串台”。现改为固定隔离：安装版使用 54328/3100/5173，源码开发版使用 54329/3101/5174，数据、PID 和日志均独立。

---

## 1. 背景

机器上存在**两套 BMPBGS 实例**。事故时两者端口相同，现在已改为固定独立端口：

| | 安装版 | 源码工程版 |
|---|---|---|
| 程序目录 | `D:\BMPBGS` | `E:\02密评\BBMPGJ\MPJG-CODEX-MASTER` |
| 数据目录 | `D:\BMPBGS-Data`（pgdata / storage / uploads / backups，由 `bb-data-path.txt` 记录） | `D:\BBMipingDB\data`（库）+ 工程内 `storage\projects`（附件） |
| 数据状态 | 昨天 22:59 被自动 initdb 的**空库**（projects=0，仅种子账号） | 昨天 18:20 的真实数据 |
| 固定端口 | 54328 / 3100 / 5173 | 54329 / 3101 / 5174 |

> 安装版空库的来历：昨天用户手删 pgdata/storage 后「恢复数据」静默失败，重启时 bb-start 自动 initdb 了新库——详见 `docs/恢复数据按钮失效-问题分析与修复方案-v1.0.md`。

**事发**：安装版三件套从昨天 23:00 启动后一直未停止（PG 占 54328、后端占 3100、前端占 5173）；用户今天从源码工程启动进程，界面连到了昨天那个空库。

## 2. 原因

1. **直接原因：源码后端是手动启动的**（`npm run dev` → `node --watch dist/server.js`），没有走 `bb-start.ps1`。
   - 手动启动不具备端口避让和数据目录解析能力；
   - `backend/src/server.ts` 第 47-48 行：未设置 `DATABASE_URL` 环境变量时，连接串默认写死为 `postgresql://bb_miping_app:...@127.0.0.1:54328/bb_miping`；
   - 此时 54328 上监听的正是安装版的空库 → 源码后端连上空库；
   - 同时 3100 被安装版后端占用，源码后端实际无法完成监听（进程随后退出）。
2. **根因：两套实例共用 54328 端口**，且安装版那套整天未停，端口与空库一直被其占据。

## 3. 解决方案（源码与安装版永久隔离）

**启动源码开发版**：

```powershell
npm run dev
```

也可双击源码根目录的 `start-local.ps1`。开发入口强制使用 `D:\BBMipingDB\data` 和 54329，若 `PG_VERSION` 不存在则立即中止，绝不自动初始化真实开发数据。

**停止或查看开发版**：

```powershell
npm run dev:stop
npm run dev:status
```

源码开发版访问 `http://127.0.0.1:5174`。安装版仍从桌面快捷方式启动并访问 `http://127.0.0.1:5173`，两套可同时运行。

## 4. 注意事项

1. 两套实例现可同时启动，但不得手工改成相同端口或互指对方数据目录。
2. **源码库数据截至昨天 18:20**；安装版那份 16:13 的备份集（`D:\BMPBGS-Data\backups\20261016-161317`）尚未恢复，属于另一条线，与本次切换互不影响。
3. **附件 storage 不互通**：源码工程的附件在工程内 `storage\projects`，安装版在 `D:\BMPBGS-Data\storage`，切换实例后早期项目的附件目录可能对不上。
4. 源码开发统一使用 `npm run dev`；直接运行后端子工程时如未显式配置 `DATABASE_URL`，后端会报错退出，不再猜测 54328。
