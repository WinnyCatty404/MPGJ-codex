## 一、需求

系统里添加图片的位置较多，目前只有拓扑图支持排序。本次需要：

1. 现场测评证据库里，**同一个证据组（同一个图编号）内的多张图片**可以左右调整先后；
2. 第四步附录B 的多图槽（如 B.1、B.2 出差/票据/发票、B.3、B.4、B.6）里的多张图片可以左右调整先后；
3. 交互为**左右箭头按钮**，不做拖拽，不做上下移动。

## 二、现状调研（结论）

### 2.1 系统里可以添加图片的位置

| 位置 | 添加方式 | 当前能否排序 |
| --- | --- | --- |
| 第三步·现场测评 → 证据库 | Ctrl+V 粘贴 / 批量导入 / 导入多张 | ❌ 不能 |
| 第二步·网络拓扑图及描述 | 粘贴 / 导入（图片块 + 文字块） | ✅ 已有 ↑ ↓ |
| 第四步·附录B 证明图片 | 选中槽位后 Ctrl+V / 导入（可多选） | ❌ 只能删除单张 |

### 2.2 关键数据结构与机制

**证据库（`onsiteEvidenceGroups`，声明于 src 5038 行）**

- 两层结构：证据组 `{ id, layer, no, name, images: [] }` + 组内图片 `{ id, dataUrl | fileId }`；
- 编号规则 `图A-(layer+1).N`，由 `nextOnsiteEviNo(t)` 分配；
- `renumberOnsiteEvidence(t)`（5360 行）只按**编号数值**重排编号并调用 `replaceOnsiteEvidenceReferences` 改写正文引用，**不改变数组顺序**——这就是"看起来能重编号、但顺序纹丝不动"的原因；
- 组内图片顺序 = `group.images` 的 push 顺序（粘贴/导入先后）；
- 删除单张图片的标准收尾三步：`refreshOnsiteEvidenceLibrary(group.layer)` + `markOnsiteEvidenceChanged()`（`deleteOnsiteEvidenceImage`，5509 行）。

**附录B（`appendixBImages`，声明于 src 7554 行）**

- 多图槽由 `APB_MULTI_IMAGE_KEYS` 定义：`b1-file`、`b2-travel`、`b2-bill`、`b2-invoice`、`b3-photo`、`b4-auth`、`b6`；
- 取值统一走 `apbImageList(key)`（兼容历史单张字符串）；
- 删除单张的标准收尾三步：`images.splice` → `renderAppendixB()` → `dispatchEvent('bb:prototype-change')`（`apbDeleteImage`，7751 行）。

### 2.3 现有样式锚点

- `.evi-thumb` / `.evi-thumb-del`（772–774 行）：缩略图 82×62，删除按钮为右上角圆形白底红字；
- `.apb-image-item` / `.apb-image-item .apb-img-del`（875–877 行）：150px 宽卡片，删除按钮右上圆形白底。

## 三、实施方案

### 3.1 变更一：证据组内图片左右移动

**新增函数**（放在 `deleteOnsiteEvidenceImage` 附近，src 5509 行区域）：

```javascript
  // 组内图片左右换位：只改 group.images 的数组顺序，证据编号不变，正文引用不受影响。
  function moveOnsiteEvidenceImage(groupId, imageId, dir) {
    const group = onsiteEvidenceGroups.find(function (item) { return item.id === groupId; });
    if (!group) return;
    const images = group.images || [];
    const from = images.findIndex(function (item) { return item.id === imageId; });
    const to = from + dir;
    if (from < 0 || to < 0 || to >= images.length) return;
    const moved = images.splice(from, 1)[0];
    images.splice(to, 0, moved);
    group.images = images;
    refreshOnsiteEvidenceLibrary(group.layer);
    markOnsiteEvidenceChanged();
  }
```

**UI 改动**（`evi-group-list` 渲染，src 5613–5616 行）：每张缩略图在删除 × 左侧增加 `←` / `→`：

- 组内图片 ≤ 1 张时不渲染按钮；
- 首张不渲染 `←`（或 `disabled`），末张不渲染 `→`，沿用拓扑图 `moveTopologyBlock` 的禁用写法；
- 按钮 `onclick` 需 `event.stopPropagation()`，避免触发缩略图的预览事件。

**新增样式**（紧跟 `.evi-thumb-del`）：

```css
    .evi-thumb-move { position:absolute; top:2px; width:18px; height:18px; line-height:16px; border-radius:9px;
      background:rgba(255,255,255,.92); color:#1a56db; text-align:center; cursor:pointer; font-weight:700; }
    .evi-thumb-move.left { left:2px; }
    .evi-thumb-move.right { left:22px; }
```

### 3.2 变更二：附录B 多图左右移动

**新增函数**（放在 `apbDeleteImage` 附近，src 7751 行区域）：

```javascript
  function apbMoveImage(key, e, index, dir) {
    if (e) e.stopPropagation();
    if (!APB_MULTI_IMAGE_KEYS.has(key)) return;
    const images = apbImageList(key);
    const to = index + dir;
    if (to < 0 || to >= images.length) return;
    const moved = images.splice(index, 1)[0];
    images.splice(to, 0, moved);
    appendixBImages[key] = images;
    renderAppendixB();
    document.dispatchEvent(new CustomEvent('bb:prototype-change'));
  }
```

**UI 改动**（`apbImgSlot` 的 `apb-image-item`，src 7704–7709 行）：多图槽（且张数 > 1）每张图加 `←` / `→`，首尾禁用；单图槽（B.5 等）保持原样。

**新增样式**：`.apb-img-move`（参照 `.apb-img-del`，颜色改为中性蓝），左移动按钮置于左上、右移动按钮置于删除按钮左侧。

### 3.3 明确不做

- 不改证据编号 `图A-x.N`；不做证据组之间的排序；不触碰 `renumberOnsiteEvidence`；
- 不做拖拽排序；不做上下移动。

## 四、影响面与风险

| 项 | 说明 |
| --- | --- |
| 报告展示 / Word 导出 | 证据图按 `group.images` 顺序、附录B 按 `apbImageList` 顺序输出 → **自动同步**，后端无需改动 |
| 结果记录正文 | 编号不变、引用不变，不受影响 |
| 持久化 | 两处均复用现有保存钩子（证据库 `markOnsiteEvidenceChanged`；附录B `bb:prototype-change`），移动后自动落库——避免重蹈"上移/下移不触发自动保存"的覆辙 |
| 风险 | 极低：纯数组换位 + 重渲染，不涉及编号与引用改写 |
